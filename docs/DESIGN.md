# 设计契约

本文件是界面的**当前契约**：有效的视觉与交互规则、验证方法与开放问题。

- 产品结构（信息架构、路由、页面职责、术语、路径、旧入口映射）在 [PRODUCT.md](./PRODUCT.md)。
- 工程、数据、安全与协作规则在 [AGENTS.md](../AGENTS.md)。快捷键清单在 [SHORTCUTS.md](./SHORTCUTS.md)。

文中的比例、尺寸、布局描述的是**当前实现**，用来保证实现与验收口径一致，**不是设计限制**。
组件、token、页面结构、交互方式都可以按用户目标重做；重做时同步更新实现、测试与本文。

---

## 1. 决策权限

### 1.1 授权

用户提出界面优化或重设计时，AI 应按目标形成完整方案并自行落地，包括：

- 信息架构：导航结构、页面划分、入口位置、页面职责的呈现方式、路由与面包屑方案。
- 布局：容器宽度、栅格与列数、断点、页面区块顺序、留白节奏。
- 视觉系统：token 取值、主题方案、配色、字号阶、圆角、描边、阴影、动效与材质。
- 组件：拆分、合并、替换现有展示组件；交互控件换成别的形态。
- 交互：打开方式、筛选与搜索的形态、多选与浮层的行为、动效与反馈方式。

改动的范围由用户目标决定，不必局限为局部样式补丁。复用现有组件是选择，不是目标。

### 1.2 不授权

设计调整不自动带来下列许可：

- 删除功能、改变 API 契约或数据语义、重置用户偏好。
- 绕过路径安全与访问门禁，或放宽媒体只读边界。
- 降低可访问性下限（见 §8.3）。
- 牺牲大库下的首屏与滚动性能（见 §10）。

### 1.3 禁止事项

- **禁止用旧组件结构、旧截图与既有布局断言限制新设计。** 组件测试里的区块位置、E2E 里的列数、
  布局审计里的跨页左缘一致，都是**当前方案的回归基线**：采用新方案时同步更新断言与审计适用范围，
  在提交说明里解释变化。不得为了保住旧断言而放弃更好的方案，也不得只跳过失败或删验证来制造通过。
- **禁止把历史像素值当作规范。** 字号、圆角、间距、容器宽度这些数值写在 token 里，token 的取值可以整体重做；
  但"数值集中在 token、组件不写死"这条规则不变。
- **禁止先定视觉再补功能。** 方案要说明它改善的是哪条用户路径上的什么体验。

## 2. 视觉与交互原则

这十条是判断方案好坏的依据，不是可以逐条打勾的清单。方案与原则冲突时，说明理由。

1. **内容是主角。** 界面外壳（画布、卡片、侧栏、描边、浮层）让位给媒体本身。
   照片与漫画是页面上唯一有彩色的东西；强调色服务于状态与当前工作台，不与内容争抢注意力。
2. **一个动作一个位置。** 信息与它的动作相邻；同一个动作不在多处重复出现；
   重复出现的入口必须带来新信息，否则删掉一个。
3. **层级靠排版与留白，不靠装饰。** 一块面板是一块面板，不套"卡片里的卡片"；
   分区靠标题条、间距与分隔线说清，不靠层层描边。
4. **两种模式两种气质，一套机制。** 照片与漫画在材质与色调上可区分，但共用同一套 token 机制、
   同一套控件尺寸、同一套骨架规则，不做成两个产品。
5. **状态诚实。** 数字带口径，耗时算不出来就说算不出来，失败说清坏的是哪一块。
   空态、错误、进度三态分开，不混成一句话。
6. **可预测的位置与返回。** 筛选与视图状态住在地址栏里，刷新不丢、后退退得回；
   直接打开的深链有确定的返回落点。
7. **触屏与键盘同等可用。** 命中区、焦点可见性、语义标签与快捷键是同等的一等公民，
   不是桌面版的降级。
8. **宽屏优先。** 24 寸与 27 寸是主战场：内容占满可用宽度，不留半屏空白；
   窄屏是同一套界面的另一种排布，不是简化版。
9. **写操作显式且次级。** 会改数据的操作说清改了什么、能否撤销、会不会影响原始文件；
   它们不占主导航的一级位置，也不挂在主操作按钮上。
10. **性能是体验的一部分。** 首屏、大图取档、虚拟滚动在真实库规模下必须成立；
    优化有基线、有前后对比。

## 3. 界面骨架与页面节奏

### 3.1 三种骨架

页头形态跟着内容走，页面不自定一套：

| 骨架 | 页头 | 用在哪 |
| --- | --- | --- |
| 标准页头 | 眉标 · 标题 · 说明 · 右侧动作 | 列表页与工具页：图库、我的、探索、任务中心、设置 |
| 工作台页头 | 眉标 · 标题 · 说明，动作在标题行右端 | 两个工作台的首页 |
| 沉浸窄条 | 一行细条：返回 · 面包屑 · 标题 + 右侧动作 | 照片墙类页面：相册详情、年份墙、人物详情、地点详情 |

共同点：标题只有一档语言，控件只有一套尺寸。同一类页面之间不换字号阶。

### 3.2 容器与留白

- **全站只有一个内容容器。** 任何视口下每一页的左右留白、内容左缘、内容宽度是同一组值；
  24 寸与 27 寸的差别只是"多放得下一些"，不是"换成另一套版式"。
- 照片墙一类内容通栏铺满主区，不套窄壳——一张照片旁边空着半屏灰地，等于把它缩小了。
- 页面纵向只有三层：页头 → 区块标题 → 内容。区块间距成倍进位（段与段 > 段内），
  组件里不写具体数值，间距关系由 token 决定。

### 3.3 工具条与筛选条

- 列表页顶部只有一行控件：视图切换、计数、排序、视图模式、批量选择入口排在同一条工具条上。
  批量选择的入口不单独占一行浮在网格上方；进入多选后，工具条上换成那一排批量动作。
- 同一类互斥选项（增量 / 全量、网格 / 列表、明暗主题）用同一种分段控件，形状一致。
- 筛选条上的控件高度一致；筛选项逐条可去掉，生效条件另起一行摆成可去掉的标签。
- 排序与视图控件贴着它管的内容，不放在页面顶部离内容很远的地方。

### 3.4 密度

照片墙的密度默认是**算出来的**：按数量、比例与视口试排几档行高，在放得下的档位里挑照片最大的那一档；
少图时把画面让给每一张，多图时保持浏览密度。窄屏另有一行至少两张的上限。
用户明确选过手动档之后不再自动插手。相册页与设置页用同一个控件。

### 3.5 空态与错误

- **失败有三种说法**：整页取不出来用空态（标题说哪里坏了，给重试）；页面还能看但某一块取不出来
  用横条（`ErrorBanner`，能重试就给手柄，"还能用但有一件没成"用 warning 语气）；表单里某一项失败用行内一行字。
  同一处失败在界面上只有一个长相。
- **空态不是标题，是一句话。** 空态标题用区块标题那一档，默认只占约四分之一屏，不撑满一屏。
- **空态一律带图标**，图标按语义选（找不到用放大镜，筛选后为空用漏斗，收藏用星标，最近用时钟）。
- **"这一侧没有内容"与"整个库还没内容"是两种空态**：前者引导去设置里改属性或去另一边看看，
  后者引导先配置媒体目录。混成一句话会把人指到错误的地方。
- 空态与提示里的每个数字都要有口径；给不出可信数字时写"算不出来"，不要给一个假的 0。

### 3.6 属性面板与弹窗

- **属性面板用规格表**：标签在左一窄列、值在右、行间一条分隔线。堆叠写法（标签在上、值在下）
  八个字段就能把面板撑到近 600px 高，下面大半是空的，而规格表本来就该横向扫读。
- 规格表的标签跟着侧走：漫画卷写「页面 10 页」，照片写「图片 10 张」；卷另有一行「所属作品」，
  否则这条记录讲不清是哪一部的哪一卷。
- 弹窗的焦点、Esc 与背景隔离按 §7 的浮层规则。

## 4. 媒体呈现

### 4.1 封面

- **照片侧方形，漫画侧竖版**：两侧一眼能分辨。竖版取 4:5 而不是更瘦的比例——
  封面太瘦会把横向素材裁到认不出内容。
- **封面自己带信息**：漫画封面上印着作品名与卷名（卷名只写"第 1 卷"时，一屏里分不出属于哪部作品），
  封面下方不重复标题；带装订边与厚度，与网格卡、页头封面同一套轮廓。
- **多图拼贴按画幅拼**：方形封面切竖条，竖版封面上下切；拼贴的每格都还要有内容，
  不是几块色块。
- **照片不裁成方的**：方形槽位里按原比例完整放进，照片没占满的地方用同一张照片放大虚化铺底。
  槽位是方的，照片不是被裁成方的。
- **视频封面裁切填满画幅**：方形裱框里保留 16:9 完整画面会读成一只空信箱。

### 4.2 照片墙

- 按真实宽高比排布，一行放得下就继续放，放不下换行；每行等比缩放铺满容器宽度。
- **末行与上面的行一样高**：不为填满宽度把一张图撑成巨幅，末行只是没铺满。
- 未知尺寸退回默认比例，服务端给出真实宽高后即刻使用。
- **相似折叠是显示方式不是筛选**：开着时墙上只留每组的代表照片，条上写清折叠了几组几张；
  点开一组就地摊开，成员聚到代表照片后面。角标挂在代表照片上。

### 4.3 取档与清晰度

- 渲染图按**元素实际显示宽**取档，不按视口宽：一张大图在窄舞台里只显示一小半，
  按视口宽取会一路顶到最高档，把整张原图拉下来。
- **渲染图不放大**：小图当封面时由浏览器放大显示，会发虚；档位不够就是不够，不假装清晰。
- 封面取哪一档由槽位的实际宽度决定，不写死固定档位。

### 4.4 缩略图与失败的媒体

缩略图取不到时留一块底色与图形记号，而不是一个空框——空框看着像没加载出来。
解码失败的图片明确标为"无法解码"，与"还没加载"分开。

## 5. 两种内容属性与阅读器

### 5.1 两种内容属性在界面上的分野

照片目录与漫画目录是两种产品，不是同一套交互换皮：

| | 照片 | 漫画 |
| --- | --- | --- |
| 点击相册之后 | 进入照片墙 | 进入阅读器 |
| 主画面 | 按真实宽高比自适应排布的平铺网格 | 单张图片适应屏幕 |
| 交互 | 点开大图、缩放、拖动、全屏、上一张 / 下一张 | 翻页、连续滚动、双页、RTL / LTR、缩放、适配 |
| 状态 | 不留进度 | 阅读进度、已读 / 未读、双页计数 |

属性只由所属媒体根决定，互斥且只能选一个；目录下的相册与集合一并继承，不按图片数量推断，
也没有单本相册的归类动作。两类的偏好与导航互不污染：偏好分存在不同的存储里，进度只有漫画才有。

照片墙的视觉基调跟随应用主题（它是浏览页），大图预览是暗场浮层（它是沉浸场景）；
阅读器整屏暗场，浮层与控件用白色系。两者不共享同一套外壳。

### 5.2 阅读器

阅读器整屏脱离外壳，暗场，浮层与控件用白色系。它有自己的骨架，不与照片墙共用外壳。

- **位置信息常驻，操作入口按需出现。** 顶部条与底部页码进度条不淡出；底部浮动工具条空闲后淡出，
  鼠标靠近底部或按下任意键就回来。淡出的只是操作入口，不是"现在读到第几页"。
- **顶栏是两块浮层，不是一条通栏。** 通栏浮层会永久压住画面顶端，而漫画页的头尾正是最不该被遮住的地方。
  拆成左侧（返回 · 书名 · 页码）与右侧（收藏 · 全屏 · 更多）两块，中间留白透到画面上。
- **顶栏的书名带作品**：写"星海漫步 · 第 1 卷"，与书封上的写法一致。
- **画布给常驻控件留出两条带**，页面永远落在两条带之间；"按高度适配"参照的是画布高度而不是视口高度。
- **双页并排时每一页都要落进画布**：竖版页按半宽铺开会高出画布，上缘被切掉。
- **进度是"当前视图实际展示的最末页"**：单页是当前页，双页是右侧页，连续是可见区末页。
- **目录浮层**要回答"现在在第几页"和"那一页在哪"：有层级，当前页一眼认出来；
  缩略图取不到时留底色与页形记号。
- **读完的收尾提示与底部工具条不叠**：两层各归各位，提示在工具条之上。
- 视频相册与图片相册是两套模型（视频记播放位置，图片记页码），互不覆盖。

## 6. 浮层、焦点与键盘

- **模态用原生 `<dialog>` 的 `showModal()`**：自带焦点陷阱、背景不可聚焦、Esc 交回本层处理。
  不用 `role="dialog"` 假装是模态——那样 Tab 会跑到背后的内容上。
- **Esc 有层级**：先收信息面板，再退目录，再退出预览；两层浮层不抢同一个键。
- **关闭浮层后焦点回到打开它的那个元素**。
- **大图预览与并排对比共用一把尺子**：两侧同时缩放、同时平移，底部只有一处缩放读数。
  对比浮层开在大图预览之上时，预览不接按键。
- **快捷键清单只有一份**（前端 `utils/shortcutsTable.ts` 与 `docs/SHORTCUTS.md`），
  帮助浮层按模式列出：只属于一个模式的键不在另一个模式下出现。模式切换刻意不占快捷键。
- 页面内分区用页签条：选中项有明确选中态与面板归属，读屏知道这一页分几段、现在在哪一段；
  页签 id 进 URL，前进后退与深链都跟着走；切页签不重挂页面、不丢草稿。

## 7. 触摸与安全区

- **命中区按控件算，不按墨迹算**：触摸档控件撑到 44×44，桌面档文字按钮不低于 28px。
  尺寸写在样式表里而不是工具类（工具类的 CSS 排在样式表之后，触摸档那一档会落空）。
- **不用伪元素撑命中区**：伪元素会覆盖控件自己的 `::after`，并吃掉邻座的点击——
  "够大"会变成"点错"。放大本体没有这两个问题。
- **"悬停才出现"的东西在触摸端常驻**：动作类元素（角标、按钮、方向标）藏着等于没有；
  纯装饰的（封面渐变遮罩）仍属悬停。显隐由统一的语义类管，组件里不各写一套。
- **抽屉是模态**：打开时焦点关在抽屉内、背景 `inert`、正文锁滚，关闭后焦点回到触发按钮。
- **贴边内容让开安全区**：带刘海与手势条的设备上，标题不钻进刘海，浮层不压在 Home 指示条上。
- **软键盘弹出时贴底浮层上移**，依据可视视口与布局视口之差；不重排整页。

## 8. 主题与视觉系统

### 8.1 token 单源

- 视觉值只有一份来源：CSS 变量定义，Tailwind 的 `borderRadius` / `fontSize` / 颜色映射到同一批变量。
  组件里不写死数值，也不写死 hex。
- **颜色 token 要么在 Tailwind 里映射，要么就别在组件里用它**：工具类不存在时不会报错，
  只会安静地不生效。
- 字号每一档只承担一个角色；中文正文不低于 12.5px，徽章一档（11.5px）只允许拉丁字母与数字，
  带汉字的徽章一律升到次要信息档。

### 8.2 语义色分工

| token | 职责 |
| --- | --- |
| `--brand` | 品牌标记、眉标、焦点环、当前工作台的悬停态。跟着工作台模式走（照片冷、漫画暖）。 |
| `--brand-contrast` | 压在品牌色上的文字色。品牌色在明暗两主题下翻转，这一项必须一起翻。 |
| `--favorite` | 收藏专用色。**不跟模式走**——收藏是全局一份数据，颜色也该全局一致；避开 `--warning` 与 `--brand`。 |
| `--warning` | 只表示扫描与加载告警。 |
| `--focus` | 焦点环。用品牌色，因为焦点属于当前工作台。 |

- 精选刻意不走 `--favorite`：同一个颜色表示两件事会互相干扰。精选标记本身是中性黑白，
  照片是页面上唯一的彩色，标记不该去抢注意力。
- **主题在首帧之前定下来**：`data-theme` 与 `data-mode` 决定整页配色，等 React 挂载再写会闪一下。
  `<meta name="color-scheme">` 也要有，否则用户选了深色而浏览器画的控件还是浅色。
- 悬停与焦点同源：卡片标题在悬停时也换成品牌色——这一下动作发生在哪个工作台里，
  就带上哪个工作台的色。

### 8.3 无障碍下限

这些是**质量下限**，不是设计偏好；改动它们要同步改审计判据。

| 项 | 下限 | 豁免 |
| --- | --- | --- |
| 正文字号 | 12.5px | 徽章一档 11.5px（仅拉丁字母与数字） |
| 桌面控件高度 | 28px | `sr-only`、勾选框与单选钮本体（点的是 label）、正文行内链接 |
| 触摸命中区 | 44×44 | 同上 |
| 文字对比度 | AA | — |
| 焦点可见 | 必须 | — |
| 减少动态效果 | 尊重系统偏好 | — |

明暗主题都要实际检查，不能只看一种。

## 9. 布局与响应式

- **宽屏优先**：24 寸与 27 寸上内容占满可用宽度。超宽档仍是单栏，只放大列宽与卡片；
  **不做"左叙述右陈列"两栏骨架**——排序控件离它排序的内容隔着半屏，筛选得贴着它管的内容。
- **断点跟容器走，不跟视口走**：卡片与分组各自是排版容器，容器够宽时设置行排成两列，
  同一张卡在两块屏上是同一套排法。需要容器查询时用浏览器原生 `@container`，不为此加依赖。
- **窄屏（390px）必须成立**：宽度一起看。模式专属规则压过窄屏规则这类问题只在窄屏上暴露。
- 服务端字段行一律上下堆：每组只有几百像素，标签与输入框并排会把标签挤成一列竖字。
- **全站统一一个容器**，不留"照片墙通栏、列表窄壳"两套宽度，翻页时内容左右跳。

## 10. 虚拟网格与大库性能

- 相册摘要由虚拟化网格承载；照片墙的行高由自适应排布算法确定，虚拟化只按行虚拟化、不参与测量行高。
- 排布算法是纯函数；容器宽度变化时重排，已渲染的行不因后续页到达而跳动。
- **视口余量不能贪心**：数值过大会让虚拟列表的尺寸树在一次测量里展开过深，
  触发栈溢出并被错误边界接管。单元测试对余量参数设上限断言。
- 保留服务端总数对应的轻量占位槽，远距离滚动后持续补页；分页失败保留已加载内容并支持重试。
- 修改虚拟化、窗口或容器后，检查拖到底部、返回顶部、远距离跳转、分页失败重试、断点与密度切换；
  崩溃探针固定相册、访问次数、视口与缩略图来源。单次打开零崩溃不能证明所有场景无异常。
- 首屏体积有预算（见 §11.3）；样式表按页面拆开，跟着各自的懒加载路由走。
- 拆分的判据是"这条规则用到的每一个类都属于同一页"：混着共享类名的规则留在原处，
  搬走会改变它与共享规则的层叠先后。

## 11. 验证方法

### 11.1 通用要求

- 每次界面改动后**基于当前源码重建并启动**，再截取受影响页面的实际运行画面；
  逐张检查并修正，直到截图反映最终代码。不能用旧二进制、旧截图或仅通过静态检查代替。
- 先说明这次设计要改善的用户体验与视觉方向，再用实际页面验证。
- 从完整页面判断信息结构、主次、图文比例、密度、留白节奏与跨页连贯性。
- 用真实数据状态检查方案：横竖图、视频、长标题、少量与大量内容、空态。
- 宽度一起看，至少截一次 390px。
- 截图检查与功能验证共同形成结论。审计全绿只代表它覆盖的技术检查通过，不等于设计完成。

### 11.2 命令

在 `frontend/` 下运行，默认连接已启动的 `http://127.0.0.1:5173`；需要 Playwright Chromium
（首次执行 `npx playwright install chromium`）：

```sh
npm run audit:layout
npm run audit:layout -- --self-test          # 审计自己的判据（不连服务）
npm run audit:contrast
npm run audit:contrast -- --self-test
```

### 11.3 门禁与基线

布局审计同时是门禁，以下任何一条不成立都会让它以 1 退出：

| 门禁 | 判据 | 豁免 |
| --- | --- | --- |
| 横向溢出 | 任一页内容宽出视口 | 无 |
| 跨页左缘一致 | 同一断点下各页的内容左缘相差不超过 2px | 阅读器（整屏暗场，自成一套） |
| 容器一致 | 同一断点下各页的内容容器左右边界逐页相等 | 阅读器 |
| 字号 | 没有低于最小字号档的文字 | 无 |
| 控件高度 | 没有低于下限的控件 | 见 §8.3 |
| 有效命中区 | 触摸档下没有命不中的控件 | 见 §8.3 |
| 抽屉的模态语义 | 触摸档下焦点不外逃、背景 inert、正文锁滚 | 宽屏 |
| 软键盘遮挡 | 触摸档下聚焦输入框后不被键盘遮住 | 宽屏 |

跨页左缘与容器一致这两条服务于"全站一个容器"这条规则；采用不同的页面布局时要同步更新审计的
适用范围，而不是删掉这条门禁。页面崩溃单独报错，不能算作空页面通过。

对比度审计走文字 DOM、图片上文字像素、图标像素三条通道；背板按几何交叠与绘制顺序确定，
不能只查祖先链。像素包围盒须完全位于截图内，自身底色取中位数附近的簇，排除抗锯齿过渡带，
避免药丸角标假阳性。每增加判定路径都补已知好坏样本并运行 `--self-test`。

体积基线（生产构建、1440×900、首页）：

| 指标 | 值 |
| --- | --- |
| 静态载荷 | 108.6 KB（预算 120 KB） |
| 构建产物首屏 | 362.2 KB（预算 420 KB，未压缩） |
| 请求数 | 72 |
| FCP / LCP | 200ms / 356ms |

媒体字节不进预算——它随库里有多少张照片变化，守不住也没意义。

## 12. 未解决问题

### 12.1 人物分组的真实准确率

已有一套人工核对过的本机标注集（真实照片 51 张、81 张脸、42 个匿名身份，身份按"同一张照片里同一个人
只出现一次"的硬约束求解，并逐组目视核对），并在 RTX 3060 上跑出完整对照：quality-v2 检测 P/R
0.872/0.926、身份 pairwise 0.778/0.656；Buffalo_m 整图 0.915/0.926、0.820/0.641；Buffalo_m 分块检测
1.000/1.000、身份 pairwise 0.827/0.672。复核层前后对照：旧口径 0/11 个重复分组对被摆到用户面前，
新口径 2/11（召回 0.182、准确率 1.000）。

仍缺的是样本量——51 张照片只能说明量级，不能定阈值；剩余 9 个漏召回的两组之间最高相似度落在
0.665～0.782，继续放宽门槛要靠更大的标注集校准，否则会把不同的人也摆到一起。场景覆盖也不全：
标注集目前集中在合照与侧脸，逆光、遮挡、跨年龄还没有真实样本。GPU 显存峰值仍未测，需要设备侧 profiler。

### 12.2 相似照片的误报率

本机库逐组目视核对过若干组，近似重复与连拍分组都站得住；但"相似但不同"的两张照片之间的边界只有
启发式阈值，没有构造一套标注集来量化误报率与漏报率。

### 12.3 活动变更的整文件重写

同会话图片写入已串行合并，重复进度不写盘；实际页码或播放位置变化仍重写 `activity.json`，
大库下的布局优化与迁移需另行评估。

### 12.4 PWA / 离线

`index.html` 没有 manifest 与 service worker，装不成可安装的离线应用。媒体请求的长期缓存已解决：
渲染图 URL 带内容版本号，服务端回 immutable；带内容哈希的静态产物也回 immutable。

### 12.5 真实标签页的视觉复核

已用一份带真实标签的临时库复核过：目录名里带「测试 / 空 格 / C++ / 100% / 字面%20 / 字面%2F /
字面%25」的相册，扫描后这些标签逐个出现在标签页上，标题按字面显示（`字面%2F` 不会被解码成 `/`）。
本机库目前没有标签，"用户自己的库"这一档仍待将来出现真实标签时再看。
