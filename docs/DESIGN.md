# Local Gallery · 设计契约

本文件定义界面设计的决策权、体验原则与验收方法。产品定位、信息架构、页面职责、功能语义和路由以[产品契约](./PRODUCT.md)为准；工程、安全与数据边界以[协作规则](../AGENTS.md)和[架构文档](./ARCHITECTURE.md)为准。

本契约给出体验质量要求，不规定固定的组件树、页面骨架、封面比例或像素级布局；但**设计系统本身是定下来的**：§4.1–§4.5 的配色、字号阶梯、圆角、组件形态与容器变体是这套界面的地基，改版时要么沿用，要么连同契约一起改。旧截图、现有布局和审计断言只描述当前实现；目标要求更好时，应随实现一起调整验证基线。

## 1. 决策权限

### 1.1 设计授权

用户提出界面优化或重设计时，AI 可按目标重做信息架构、导航、页面职责呈现、布局、主题、token、组件与交互。可以拆分、合并或替换旧组件，复用旧结构不是目标。

设计方案应说明它改善了哪条用户路径、移除了什么困惑或重复，并符合 PRODUCT 中的功能与路由契约。改路由时保留既有书签可用，按产品契约重定向旧路径。

### 1.2 必须保留的边界

重设计不自动授权删除功能、改 API 或数据语义、重置用户偏好、绕过访问控制、写入或破坏原始媒体、降低无障碍要求或牺牲大库性能。详细边界分别见 PRODUCT、AGENTS 与 ARCHITECTURE。

### 1.3 回归基线

旧组件结构、截图、页面左右边缘、网格列数和固定尺寸都不是设计规范。新方案改变这些结果时，同步改实现、测试与审计的适用范围，并说明改变原因。保留与新方案相关的功能、路径安全、无障碍、溢出和稳定性验证；不得仅跳过或删除失败检查来制造通过。

新方案改变了产品结构（入口、职责、路由）时，在同一个改动里同步修改[产品契约](./PRODUCT.md)：
契约随**已经验证过**的交互一起演进，不要求先有旧结构的许可，也不允许实现先跑在契约前面。
安全、媒体只读、性能与无障碍这些底线不随契约一起变。

## 2. 体验原则

1. **媒体优先。** 页面先回答用户要看、找、发现、整理或阅读什么；技术能力作为支撑，不抢内容的注意力。
2. **结果优先。** 用户是来看东西的，不是来读说明的。页面先给结果（照片、内容、命中项），再给解释与控制；入口、统计与说明不排在结果前面，也不能挤掉第一屏的内容。
3. **降低导航层级。** 从入口到内容之间别隔着太多层：能在当前页解决的不要让用户再跳一页，能合并的列表不要拆成好几页。深链打开的页面也要有确定的落点，不把用户丢回起点。
4. **保持来源上下文。** 从哪里来的要看得出来，回去也要回得去：面包屑、所属集合与作品、筛选与视图都留在页面上。适合分享或恢复的状态（目录、筛选、视图、页签）写进地址，刷新与前进后退都跟着走。
5. **层级清楚。** 每屏有明确的主任务和下一步。标题、留白、位置与视觉强调共同表达主次，避免重复入口和无目的装饰。
6. **两种工作台各有语气。** 照片强调发现和浏览，漫画强调连续阅读；共享应用的可访问性、反馈和导航机制，不强迫两侧共用同一种展示布局。
7. **状态诚实。** 加载、空结果、部分失败、完整失败和任务进度表达清楚；所有数量、时间与质量说明口径明确，无法可信计算时直说。「还没取到」不能写成「没有」：加载途中先摆一排 0 或一句「没有带位置的照片」，读的人会当成结论。
8. **操作可预测。** 页面刷新、深链、前进后退和返回都有明确结果；适合分享或恢复的筛选与页签状态能由地址表达。
9. **操作与反馈一致。** 同一个动作在全站有同一个名字、同一个位置、同一套反馈：收藏就是收藏、返回就是返回，写入成功与失败都有可理解的提示。控件的位置与措辞不随页面变，用户学一次就到处能用。
10. **写操作可辨认。** 收藏、精选、人物修正、相似组决定等动作说明对象和结果；需要确认或撤销时按影响范围处理，不把整理动作伪装成浏览。
11. **真实照片优先。** 用真实内容占位，不用示意图、纯图标或空白格代替照片；没有内容时说清缺什么、为什么缺、下一步去哪，而不是摆一个点下去空无一物的入口。目录、文件夹这类容器条目同样用里面的真实内容占位：摆一块灰底加一枚图标，读的人既看不出里面有什么，一屏灰块也把内容挤没了。
12. **触屏、键盘和读屏都能完成任务。** 不把悬停作为唯一入口，状态不只靠颜色区分，焦点、名称、操作结果都能被感知。
13. **适配内容与视口。** 宽屏、窄屏、触摸和键盘都是完整界面。布局随内容和任务选择，不为跨页对齐而牺牲可读性或媒体呈现。
14. **性能属于体验。** 首屏、媒体取档、分页和虚拟列表要在真实的大库中成立；优化需有可复现的前后证据。

## 3. 交互契约

- **不同搜索回答不同问题。** 名称搜索用于定位相册、集合、作品或标签；内容搜索用于按画面或图片文字找照片。页面要说明搜索范围，不能用同一输入框暗示检索能力相同。
- **对象类型要可辨。** 相册、集合、作品、卷、文件夹、主题与人物候选按 PRODUCT 的含义命名；资源级收藏与照片级精选使用不同名称和可辨认的图形/状态。
- **标题与计数说得同一件事。** 一屏摆着哪几类资源，标题与计数就说哪几类；混合展示时不能把标题写成其中一种。计数的口径（多少本、多少张、多少个视频）在页面之间一致。
- **导航和状态配合。** 路由、页签、适合深链的筛选及模式切换应与浏览器历史一致。局部临时状态无需全部写进地址栏。
- **返回有确定的落点。** 有历史就回退；没有历史（深链）时回到能确认的父级或来源（见 PRODUCT §8），落点不能指回当前页，也不能让用户在两页之间来回打转。
- **对话框和浮层有完整键盘路径。** 打开后焦点进入合理位置；模态内容不能把焦点送到背景；Esc 按层级关闭；关闭后焦点回到触发点。非模态浮层不伪装成模态。
- **反馈贴近操作。** 写入成功、失败、等待与取消有可理解的反馈；可重试的失败给出重试入口。部分页面仍可用时，不把单一区块失败说成整页不可用。
- **写操作留下退路。** 会让内容从眼前消失的写操作（例如把一组标记为已处理后它离开待处理列表）给一条带「撤销」的提示；撤销按每一组操作前的那一档恢复（不统一翻一个布尔），撤销之后仍然说清结果。
- **少量内容不摆成墙。** 挑出来的三五张照片不按密排的墙摆：每张一个框，完整地摆出来（不裁、不拉伸），框按照片自己的形状长，几个框并排摆开、整体居中，出处写在照片下面。用户挑出来的照片是拿来好好看的，不是拿来数的。
- **时间要可信。** 按时间组织内容时，每一段时间的来源要分清：拍摄时间、从文件名或目录名推断出来的日期、只有文件修改时间。推断出来的必须标出来，不能冒充拍摄时间；没有拍摄证据的媒体单独成段，不混进任何一年充当那年的照片。
- **按时间浏览要有落点。** 时间线按月分段，每段有自己的标题与数量；跳年、跳月与按照片或视频筛选是地址的一部分，刷新不丢、后退退得回、能分享。
- **目录要能找回位置。** 目录树默认只展开当前位置相关的那条路，其余收起；每一层都能单独收起；能按名字定位并跳过去；有面包屑，也有「返回上一级」。走进多深都要能一级一级退回来。
- **同一批照片只有一套。** 分组（按时间、人物、地点、场景）是同一本相册里照片的一种看法，不是另一本相册：切换分组不改变原始文件与筛选结果，数量说清现在看的是哪一段，并有明确的恢复入口。
- **两套条件不许互相静默忽略。** 筛选条件与分组都是缩小范围的手段，但它们不叠加：进入某个具体分组时，与它冲突的筛选条件被**明确结束**（地址栏一并去掉、界面给出提示、分组视图里常驻说明），回到全部照片看到的是真正的全部照片，不意外恢复一条已经被结束的筛选。地址栏、页面上的条件标签、实际数据与结果计数说的是同一件事。
- **同一行的多个筛选控件各自说清自己管什么。** 两组分段控件并排时（比如「结果类别」与「处理状态」），按钮上的字往往重名（「全部」两边都有）。控件要有可见的标签：只靠无障碍名称区分，界面上读的人分不出哪一组是哪一个。
- **自动纠错不改写用户的意图。** 内容失效（分组被删、被重建、ID 失效）时页面自己纠正回来，但纠正**改写当前那条地址**，不往历史里追加失效的地址；用户主动的选择仍然进历史，前进、后退、刷新与深链都不形成循环。
- **失败要说清影响范围，并给得出恢复的手柄。** 首屏读不出来时区分断网、库变了与服务端出错，并给出重试；局部失败（后续分页）时保留已经取到的内容，用一条可恢复的提示说明哪一段没取到，而不是把整页推倒。失败状态下不自动重试成一条无限请求。
- **快捷键只有一份行为来源。** 实现与[快捷键说明](./SHORTCUTS.md)同步；快捷键不替代可见控件，也不覆盖输入、浏览器或系统的常用操作。

## 4. 视觉与媒体呈现

- 用共享 CSS token 管理视觉值，组件使用语义 token，不在组件里散落固定颜色。token 的取值见 §4.1–§4.3；改动它们时连同契约一起改。
- 语义颜色表达含义并在明暗主题中保持可辨。收藏、精选、警告、危险、当前工作台等状态同时依靠名称、形状或图标表达，不单靠色相。
- 照片和漫画可有不同的封面、阅读场景和材质，但应属于同一产品；两侧的视觉差异应帮助识别内容与操作，不只是换一组主题色。
- 两个工作台是同一套系统的两种语气，色相上各有一支：照片侧采用炭黑与象牙白，漫画侧采用暖铜赭。两个工作台共用语义角色、组件与交互。
- 媒体是内容本身。缩略图可按场景采用裁切或完整显示；重要信息不应被永久裁掉，用户需要时能查看完整画面。不得把当前封面比例或照片墙算法当成产品限制。
- 每种状态使用一致的反馈方式。空状态告诉用户缺少什么及下一步；错误指出影响范围；危险操作说明作用对象及对原始文件的影响。
- 明暗主题都需保持可读性；主题颜色与浏览器原生表单控件一致，首帧不闪烁。

### 4.1 配色与样式分层

「静观」采用纸白与暗房两套主题。照片和漫画共享画布、文字与信号蓝。漫画的主操作、封面压条采用暖铜赭。收藏与精选用同一语义色，以心形、星形区分。

| 角色 | 纸白 | 暗房 |
| --- | --- | --- |
| 画布与侧栏 | `#F7F7F5` | `#0A0A0B` |
| 抬升表面 | `#FFFFFF` | `#141416` |
| 次级表面 | `#EFEEEA` | `#1B1B1E` |
| 正文、次要文字、计数 | `#111110`、`#5A5953`、`#6F6D66` | `#F3F2EF`、`#A6A59F`、`#86857F` |
| 照片主操作 | `#111110` | `#F3F2EF` |
| 漫画主操作 | `#8A4F2D` | `#D9A074` |
| 控件选中、焦点、进度 | `#2F6BFF` | `#7FA4FF` |

颜色与尺度集中在 `styles/tokens.css`。Tailwind 使用同一份语义变量。`styles/base.css` 管理基础排版与焦点，`styles/components.css` 管理共享原语。首帧脚本按主题偏好与工作台 URL 选择颜色。正常字号文字需达到 4.5∶1，图形需达到 3∶1。语义色用于小字号文字时采用对应的文字色。

### 4.2 字号与数字

字族优先使用系统安装的 Inter、苹方与微软雅黑 UI。计数、页码、时长和速率使用等宽数字。

| 用途 | 字号 / 行高（px） | 字重 |
| --- | --- | --- |
| 展示标题 | 40 / 48 | 650 |
| 页面标题 | 30 / 38，1920px 起为 34 / 42 | 650 |
| 区块标题 | 22 / 30 | 600 |
| 月份与浮层标题 | 17 / 24 | 600 |
| 正文 | 15 / 24 | 400 |
| 卡片标题及控件 | 14 / 20 | 500 |
| 日期、来源及说明 | 13 / 18 | 400 |
| 徽标、键帽及分组名称 | 12 / 16 | 500 |

### 4.3 圆角、表面与动效

照片瓦片、徽标底板、控件、封面与浮层分别使用 4、8、10、14、20px 圆角。徽标及进度槽可使用胶囊形。区块依靠留白分组。选中项与输入框使用一级阴影，菜单使用二级阴影，对话框使用三级阴影。悬停、控件切换、抽屉转场分别使用 120、200、320ms。系统启用减少动态效果时关闭位移与微光。

### 4.4 组件形态

- 一屏最多一枚强调色主按钮。次级按钮使用细描边，弱操作在悬停时显示浅底，危险操作采用危险色。按钮有 32、40、48px 三档，加载时保留原宽并禁用重复点击。
- 标准输入框高 40px，大搜索框高 56px。聚焦使用信号蓝。搜索支持中文输入法组字，Esc 清空已有内容，再次 Esc 离开输入框。
- 图形按钮提供可访问名，鼠标与键盘可获得文字提示。开关有 40×24px 药丸和可感知的开关状态。分段使用单选组语义，页内页签支持方向键和 Home、End。
- 模态浮层接管焦点并锁定背景滚动，Esc 关闭顶层，关闭后焦点回到来源。横向列表支持触摸滑动、键盘方向键以及鼠标翻动按钮。
- 设置分组最宽 720px，分隔线在左缘内缩，标签与控件在窄屏上下排列。

### 4.5 容器变体

三种内容容器，可落在页面外壳上，也可落在页面里的某一段上。变体只改**宽度与密度**，不改左右留白：留白一变，内容左缘就离开网格线，翻页时内容会左右跳。

| 变体 | 类名 | 用来做什么 |
| --- | --- | --- |
| Gallery | `.container--gallery` | 媒体优先：照片墙与相册网格，列更宽、行距更松，照片占更多画面 |
| Standard | `.container--standard` | 通用内容页的默认节奏 |
| Focused | `.container--focused` | 聚焦：少量内容摆出来给人好好看，单栏窄内容、整体居中（1040px） |

设置与任务中心采用分栏页，导航与页头左对齐，设置正文最宽 720px，任务正文最宽 760px。少量精选使用居中陈列。

### 4.6 外壳与顶栏

1024px 起显示 240px 桌面导航，Ctrl+B 收起至 72px。收起态以图标、可访问名称及右侧提示标识入口。顶栏高 64px，中央是全局搜索，右侧是页面动作与更多菜单。页内大标题离开视口后，顶栏显示收缩标题。选中导航项使用抬升表面、实心图形与字重。

窄屏顶栏高 56px，搜索折为图标。底栏高 64px 并计入底部安全区。更多抽屉接管焦点，支持 Esc、关闭按钮和下拉把手。软键盘与沉浸浮层打开时收起底栏。照片与漫画的入口清单由产品契约第 8 节维护。

### 4.7 照片时间线

| 部位 | 规格 |
| --- | --- |
| 页头 | 全部照片、媒体数量及年份区间；同时提供类型、筛选、密度和可用的回忆或继续浏览入口 |
| 筛选浮层 | 年份、月份、类型、时间来源和日期精度；条件写入地址栏 |
| 年份标尺 | 768px 及以上显示；按照片数量分配跨度，每年保留最小空间。拖动预览月份，松手提交。窄屏通过「跳转」打开年份抽屉 |
| 月份段头 | 18px 月份标题，13px 张数与推断说明 |
| 照片墙 | 密集、标准、宽松分别留 2、4、6px 间距。同年相邻的小月份可同行，每段独立标注。跨年、日期未知和宽度不足 640px 的段独占一行 |

### 4.8 图库与相册

图库采用随容器宽度自动分列的网格，列宽下限依次为 240、260、300、340px。列表每项一行，高 64px，缩略图宽 48px。目录通过页头或快捷键打开，1280px 起在左侧占 280px，较窄时使用左侧抽屉并隔离背景焦点与滚动。面包屑各级支持查找同级目录，并保留返回上一级入口。

文件夹封面使用目录内真实照片拼贴。单图全幅、两图平分、三图左侧主图通高、四图两行两列，拼贴缝隙 2px。列表使用首图作为紧凑缩略图，照片封面比例 4:3，漫画书封比例 2:3。单个封面加载失败时在该格显示图片图标。文件夹类型图标放在计数行，收藏心形与整卡链接分别接受焦点。

照片相册的贴顶页头承载归属目录、标题、计数、分组、筛选、密度、多选、收藏与更多。视频封面裁切铺满暗场瓦片并标明视频类型。大图预览从当前瓦片放大进入纯黑画布，退出时回到当前照片。减少动态效果时使用透明度转场。胶片条限量渲染邻近照片，信息面板从右侧推开画布。

### 4.9 发现与搜索

发现使用 Standard 容器。页头与正文共用左缘。搜索框高 56px、最宽 760px，输入框和检索范围共用一行。名称结果按命中理由分组，内容结果在照片上标明画面或文字依据。索引覆盖率放在结果页脚。

| 区块 | 陈列与交互 |
| --- | --- |
| 人物 | 圆形代表脸宽 120px，宽屏 136px。待确认的头像有问号，分组说明可点击展开。 |
| 地点 | 300px 宽的 3:2 照片叠加城市、张数和访问次数。地点来源可点开阅读。 |
| 时间 | 每年占 112×72px，显示年份与真实张数。今年有信号点，进入同一日期范围的时间线。 |
| 主题 | 最多四组 4:3 封面，保留主题名、成员数和来源。 |

横向列表支持滚动、键盘与两端箭头。各区块分别呈现加载、错误与空数据。珍藏中的 1–4 张精选居中陈列，框宽上限 520px，间距 32px。更多精选保留原始比例进入瀑布流。默认排序的最近浏览按今天、昨天、本周及更早分段，每行展示相册、96px 封面和访问时间。

### 4.10 珍藏与相似整理

珍藏是「我留下的与看过的」，相似整理是「这些照片里该留哪张」。两页都以**照片本身**为主角：精选是一张张挑出来的照片，收藏是相册卡，最近浏览是访问过的相册，相似整理是待决定的一组组照片。

| 部位 | 规格 |
| --- | --- |
| 容器 | Standard：标题、页签与内容区共用一条左缘网格线 —— 三个页签摆的东西形状不同，起点必须相同 |
| 精选陈列 | 1–4 张：每张一个框，**按自己的比例摆**（不裁、不拉伸），框最宽 420px、最高 560px |
| 精选照片墙 | 5 张起：自然照片墙（瀑布流），每张按自己的比例占位，不裁不凑行 |
| 照片下方 | 来源（相册名）+ 日期；**不摆文件名** —— 文件名是文件系统里的编号，不是给人看的信息 |
| 日期 | 照服务端的 `dateValue` 显示（自己换算时区会差一天）；拿得出拍摄证据才写，文件修改时间不写 |
| 收藏 | 相册 / 资源卡片（封面 + 名字 + 数量），与精选的单张照片一眼分得清 |
| 最近浏览 | 只留「翻的是什么、什么时候翻的」：封面、相册名与一句「上次 X」；张数、视频数、目录类型不摆 |
| 相似整理 · 组 | 代表照片 200px 见方，占据每组最左边；类别、张数、多余张数与状态徽章在标题行 |
| 相似整理 · 决定 | 「标记已处理」是这一组的主要动作（细线按钮，比「展开」「加入精选」重一档）；不用强调色实底 —— 一屏几十组，实底按钮会变成一片色块 |
| 相似整理 · 展开 | 成员并排摆出，照片给足尺寸（180px 高）：这一页的正事就是比对 |
| 质量读数 | 次级排版：13px、更浅的颜色。它解释「为什么是这张」，不压过照片与那个决定 |
| 三档状态 | 待处理 / 已处理 / 已忽略：筛选与地址栏给全局视角，组上的状态徽章给出这一组的处境 |

**照片下面不摆文件名。** `IMG_20230824_224824.jpg` 是文件系统里的编号，写在照片下面读起来像一份技术清单。那里该写的是「哪本相册里的、什么时候拍的」—— 挑出来的照片正是为了记住那件事。

**精选多起来也要按自己的比例摆。** 相册里的照片墙会裁切凑行：那是给「一整本几千张」用的。精选是用户挑出来的那几张，裁掉半张脸，这一页就没有意义了。

**最近浏览只回答两个问题。** 「我刚才在翻什么」「什么时候翻的」。张数、视频数与目录类型是技术读数 —— 摆在那里只会把这两个答案挤到边上。

**相似整理的视觉中心是照片与那个决定。** 质量数字、文件时间与跨文件夹这类说明用次级排版：它们解释「为什么是这张」，但决定是用户要做的，不是读数。

### 4.11 设置与任务中心

桌面子导航宽 220px，1024px 以下移到标题下方横排。分区使用可深链的普通链接，保留已访问面板的草稿。设置行最小高度 56px，640px 以下控件排在标签下方。危险操作独立分组，确认窗口说明清空的范围。版本与快捷键提示在界面分区的关于组。

任务运行页先呈现当前运行、空闲、等待队列或最近失败状态。运行时显示进度、处理数、失败数、速率与预计剩余时间，主要操作紧贴状态。模块矩阵在宽容器显示五列，按宽度收拢，卡片给出就绪情况、预计张数及最近状态。状态点以蓝色标记已选中、绿色标记就绪、灰色标记不可用，选中状态也通过卡片描边和 `aria-pressed` 表达。队列、硬件、模型相关的高级信息和存储仍按页签和区块组织。

### 4.12 漫画工作台：暖棕的书架

漫画封面采用 2:3，书脊暗边宽 3px。书架以 160px 为最小列宽，宽屏提高到 200px。继续阅读区的主封面最宽 280px，封面旁展示书名、真实页码和继续阅读入口。其余在读卷横向浏览。阅读器保持暗场，菜单中的阅读设置可调整显示模式、翻页方向与页面适配。

漫画侧是书架，照片侧是展陈墙。两侧的差别落在**材质**（竖版书封、装订边、厚度、投影）与**色相**（暖铜赭与炭黑、象牙白）上，落在同一套系统里：角色名、层级、组件与交互都共用。

| 部位 | 规格 |
| --- | --- |
| 强调色 | 低饱和暖棕：浅色 `#8A4F2D`、深色 `#D9A074`，两档均达到 AA |
| 生效方式 | 只在 `:root[data-mode="comic"]` 里**重映射语义 token**：强调色一族、焦点环与侧栏选中项指向暖棕。组件里写的 `accent` / `accent-soft` / `focus` 一个都不用改 |
| 侧栏选中项 | 同一套说法换成暖棕：暖棕淡底 + 一档深棕字，不用实心填充 |
| 书名压条 | 封面下缘一条暖棕实色段（`--cover-band`），像贴在书脊上的标签；白字压在纯白封面上也有 8:1 |
| 阅读器 | 恒为暗场，控件的选中态与进度条用深色档的暖棕（`--reader-accent`）：浅色档的暖棕压在这块深底上会沉进画面 |
| 保留 | 封面竖版、装订边与书口、书名压在封面上的排法、阅读方向、单双页、连续阅读、进度恢复 —— 换色不改这些 |

**暖棕只换色相，不换系统。** 语义重映射是唯一的实现方式：组件里若出现漫画专属的颜色值，就说明模式层之外又长出了第二套颜色语言。

**书名压在封面上。** 漫画侧保留这条与照片侧相反的规矩：照片的标题在照片下面，漫画的书名印在封面上 —— 网格因此读起来是一面书架，而不是「图片 + 说明」的列表。

## 5. 无障碍与响应式

- 交互可通过键盘完成，焦点始终可见；控件具有准确的名称、角色和状态。对话框、抽屉、菜单和媒体预览有明确的焦点进入、限制与返回行为。
- 文本和图形符合对比度要求；信息不能只由颜色、位置、悬停或动效传达。触控目标大小和间距满足当前无障碍标准，并结合页面密度设计。
- 支持浏览器缩放、窄视口、触摸输入及系统减少动态效果偏好；输入聚焦时重要操作不被软键盘遮挡。
- 视觉尺寸随字体缩放与内容调整；本节规定结果要求，不锁定某个旧截图中的字号、控件高度或断点。
- 验收覆盖宽屏与窄屏、键盘与触摸，以及明暗主题。页面结构可以因任务而异，不要求全站共用一种容器或列数。

## 6. 大库性能

- 列表按需分页或虚拟化，首屏不要为了展示总量而下载全库媒体；大图和封面按实际显示需求取档。
- 服务端状态由 TanStack Query 管理，界面偏好等客户端状态由 Zustand 管理；不复制第二份长期媒体库、收藏或历史数据源。详见[架构文档](./ARCHITECTURE.md)。
- 新布局不得造成滚动位置跳动、重复取数、无界 DOM 或大图一次性解码。虚拟化、分页与缓存的实现约束以架构文档为准，设计层不固定某种布局算法。
- 涉及首屏、媒体、分页或虚拟滚动的优化，在代表性真实库上比较响应时间、滚动稳定性与内存；仅在显式性能任务中记录正式基线。旧布局的测速数字不是目标指标。

## 7. 验证方法

### 7.1 界面改动

每轮界面改动都基于当前源码重建并启动应用，验证实际 API 与 UI，再检查保存在 frontend/.smoke/<任务>/ 的截图。截图要对应最终代码，不用旧二进制或历史画面代替。

按改动范围覆盖相关模式、明暗主题、宽窄视口、关键交互与真实内容状态，例如横竖图、长标题、空态、部分失败和大量条目。截图用于检查信息结构、层级、媒体呈现、响应式与跨页体验；它是验收证据，不是下一轮设计模板。

按需运行以下 frontend 命令，并结合行为测试检查交互：

- npm run audit:layout：当前实现的溢出、触控和布局检查。
- npm run audit:contrast：当前实现的文字和图形对比检查。
- npm run audit:crash：页面崩溃探针。
- npm run audit:size：生产首屏体积检查。
- npm run shot：生成主题、视口与页面截图。
- npm run test:e2e：跨层用户路径验证。

审计覆盖的几何基线可能属于旧方案。改版后应调整或替换相应判据，同时保留适用的无障碍、溢出与崩溃检查。审计通过只证明它覆盖的技术条件通过，不单独代表设计完成。

布局审计同时验证桌面侧栏宽度、桌面正文起点、56px 贴顶主行及目录抽屉默认收起。「跨页左缘一致」判据按页型分档：分栏页（设置、任务中心，见 §4.11）检查导航与正文各自的左缘；其余页面的左缘、容器边界、溢出、文字与控件尺寸、命中区检查照旧。

沉浸页同样不参与跨页容器比对：阅读器不在 AppShell 下，通栏是有意的。漫画侧没有相册网格页（打开一卷直接进阅读器），因此审计的 `album` 伪路由在漫画侧不成立 —— 那一侧只量阅读器（`reader` 一条）。
