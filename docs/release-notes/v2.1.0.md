# v2.1.0 内部性能与一致性修复

> 这次提交覆盖后端服务、媒体管线、配置管理、前端架构与构建产物共 9 个 sub-plan
> （S1-S9）的修复 + 若干性能 bug 修复。所有变更均向后兼容，磁盘 schemaVersion
> 由 2 升到 3 是唯一破坏性变更。

## 行为变化

### 用户可感知

- **首页加载** ：扫描器取消 N+1 `os.Stat`，`FolderSize` 仍准确
- **画廊 1000 张连续滚动** ：改用 `react-virtuoso` 窗口化，DOM 节点数
  稳定在视口高度相关的小常数
- **视频 304 协商** ：修复了 `videoETag` 引号 bug（之前浏览器发的
  `If-None-Match` 永远不命中），现在与缩略图 304 行为一致
- **首次启动** ：ffmpeg 编码器自动选择延后到首次转码（不再启动期跑
  6 次 `ffmpeg -h encoder=*` 探测）
- **崩溃恢复** ：PrefsStore 落盘加 `tmp.Sync + Close + Remove`，
  损坏备份加纳秒后缀，同一秒内连续损坏不再互相覆盖
- **错误响应** ：所有 4xx/5xx 统一为 `{code, message, error?, details?}`，
  `code` 是稳定 snake_case 短串，前端可做 `if (err.code === 'video_cover_missing')`
  区分（老字段 `error` 仍保留为 message 别名）
- **路由层错误** ：任意子组件 render 抛错显示"图像库加载异常"卡片 +
  重试按钮，不再白屏

### 维护者可感知

- **扫描器并发** ：worker pool 用全局信号量跨递归共享，5 层嵌套
  树活跃 goroutine 数稳定 ≤ `min(8, NumCPU)`
- **缓存读路径** ：`ScanResultCache.Get()` 改 `atomic.Pointer.Load` 无锁，
  `ApplyCoverOverrides` / `SetWithOverrideApplied` / `RebuildCoverForAlbum`
  改 CAS 重试，stat 全部移到锁外
- **配置变更** ：`Manager.OnChange` 通知改为 goroutine 派发，listener
  慢/panic 不再阻塞 Update 主路径
- **排除规则** ：`ExcludeConfig` 预编译 patterns，遍历百万级目录时
  字符串处理从 O(N²) 降到 O(N)
- **scan_cache.json** ：schemaVersion 2 → 3，落盘直接存 raw 绝对路径；
  资源 ID 翻译（`r_/a_/c_/f_`）由 `ResourceCatalog` 全权负责。
  旧版 cache.json 启动时自动清空（用户在 UI 看到"自动扫描中"）
- **SSE 事件名** ：扫描与转码共用 status 字符串命名空间（前端可统一订阅）

## 性能改进

| 路径 | 改进 |
|---|---|
| 5k+ 相册扫描 | N+1 stat 消除（每张图省一次 syscall） |
| 5 层嵌套扫描 | goroutine 数 32K → ≤ 8 |
| 扫描缓存 Get | 无锁 atomic.Load，首页并发 50+ goroutine 不再竞争 RWMutex |
| ApplyCoverOverrides | 锁持有时间从 O(stat) 降到 O(clone) |
| 视频 handler | 每次请求 stat 从 3 降到 1 |
| 排除规则匹配 | 字符串处理 O(N²) → O(N) |
| 1000+ 连续模式 | DOM 节点从 1000+ 降到视口高度 |
| 首页 5k 相册深拷贝 | atomic snapshot 替代深拷贝，handler 不再走深拷贝 |

## 升级注意

- 升级后**第一次**启动会重新扫描（`scan_cache.json` 不兼容 schemaVersion=3，
  自动清空 + 触发自动扫描）。扫描完成后照常使用。
- 旧版 `web_settings.json`（收藏 / 历史 / 进度）格式不变，无需重置。
