# Local Gallery · 产品契约

本文件是产品结构的唯一真相源：定位、信息架构、路由、页面职责、功能语义、关键路径与旧入口映射。
视觉与交互规则在 [DESIGN.md](./DESIGN.md)，工程与协作规则在 [AGENTS.md](../AGENTS.md)。

本文件描述**目标结构**：入口的职责、路由、功能语义与关键路径。信息架构已经落地
（路由、导航与页面职责见 §2–§4、§9）；**页面骨架、板块顺序、视图组合与交互**
属于 [DESIGN.md](./DESIGN.md) 的授权范围，可以整体替换而不必回到本文件请示。

本文件约束的是「有哪些入口、各自回答什么问题、承载什么内容」；
本文件不描述「这一页长什么样、摆几块、按什么顺序」。实现与本文件不一致时，
要么改实现，要么在验证过新交互之后同步改本文件 —— 两件事都要做，不留半截。
文中出现的旧入口一律保留可用：旧路径重定向到新路径，不做 404，也不删功能。

## 1. 定位

Local Gallery 是单用户、本机优先的私人影像空间。它把本机的照片、漫画与视频组织成
**能看、能找、能探索、能整理、能接着读**的地方。

- 它不是作品管理器，不提供账号、云同步、在线分享与协作。
- 它不是文件管理器：应用对媒体目录**只读**，不移动、不改名、不删除、不覆盖任何原始文件。
- 它展示技术能力的方式只有一种——能力本身要好用；界面不解释后台做了什么。

产品重心按动词排：**观看 · 寻找 · 探索 · 整理 · 连续阅读**。任何新功能先问它服务哪个动词；
不服务这五个动词的（如"展示模型跑分""展示缓存占用"）属于系统层，放在任务中心或设置里。

### 两个工作台

媒体根目录有且只有一种内容属性：**照片**或**漫画**。属性互斥、只能选一个，由目录决定，
不按文件数量推断，也不提供单本相册的归类动作。属性决定两件事：这个内容出现在哪个工作台；
点开之后是照片墙还是阅读器。

两个工作台是两套产品，不是同一套交互换皮：

| | 照片工作台 | 漫画工作台 |
| --- | --- | --- |
| 核心动词 | 观看、寻找、探索、整理 | 连续阅读、找书 |
| 内容单位 | 相册（张） | 卷（页） |
| 结构分组 | 文件夹 | 作品 / 系列 |
| 状态 | 浏览历史（落在相册上） | 阅读进度、已读 / 未读、在读 |
| 专属能力 | 精选、主题、人物、足迹、智能筛选、相似整理 | 未读、继续阅读、标记读完 |

两个工作台**不混排**：一次只面对库的一半，菜单、列表、措辞、进度与偏好互不沾边。
收藏与历史是全局一份数据，但每个工作台只呈现属于自己这一侧的部分，界面上也不出现
"另有 N 项属于另一侧"这类提示。**"这一侧看不到"不等于"失效"**——只含漫画的标签被收藏后，
在照片工作台查不到它，但清理失效收藏绝不能把它删掉。

## 2. 信息架构

### 2.1 照片工作台

照片工作台有**四个一级入口**，各自回答一个不同的问题：

| 一级入口 | 路由 | 这一页回答的问题 | 主要内容 |
| --- | --- | --- | --- |
| **照片** | `/photo` | 我现在想看点什么 | 照片本身：按时间下来的全库时间线，配一条「那年今日」回忆入口与一枚「接着看」 |
| **相册** | `/photo/library` | 我的照片在磁盘上怎么摆 | 当前目录的通栏卡片、可展开的目录抽屉与同级目录菜单 |
| **发现** | `/photo/explore` | 有没有办法找到它 | 时间、人物、地点、主题、内容搜索这几个维度 |
| **珍藏** | `/photo/me` | 我留下的和看过的 | 三个页签：精选照片、收藏、最近浏览 |

「整理」是**次级入口**，不占一级位置：它做的是写操作（换代表、标记已处理、忽略、
批量加入精选），属于高级整理而不是日常浏览。

四个入口的分工是：**照片**给内容、**相册**给结构、**发现**给维度、**珍藏**给个人数据。
同一份内容不该在两个入口里各露一次。

**入口的职责是契约，页面骨架不是。** 这四个入口各回答一个问题、承载一类内容，
这一点固定；每个入口具体由几个页面构成、板块按什么顺序摆、用不用左右分栏、
相册页要不要提供分组面板 —— 这些都是**当前实现**，
可以在验证过更好用之后整体替换，不必因为「原来长这样」而保留。

### 2.2 漫画工作台

**漫画工作台独立于照片工作台**：它有自己的一级入口、自己的导航、自己的状态与措辞。
照片侧的四个入口（照片 / 相册 / 发现 / 珍藏）不套用到漫画侧，漫画侧的入口也不与它们混排。
两侧共享的是应用外壳、可访问性与机制，不是同一套页面骨架。

| 一级入口 | 路由 | 这一页回答的问题 | 主要内容 |
| --- | --- | --- | --- |
| **首页** | `/comic` | 我要接着读哪一本 | 继续阅读（正在读的那本 + 在读队列）、未读 |
| **书架** | `/comic/library` | 库里有哪几部作品 | 作品 / 系列 / 卷的一览与层级 |
| **我的** | `/comic/me` | 我留下的和看过的 | 三个页签：收藏、最近阅读、在读 |

「收藏」是资源级入口，可能包含相册、文件夹、作品、卷或标签；「精选照片」只包含单张照片。
因此页签统一称「收藏」，由卡片类型标明具体对象，避免把集合与标签误说成相册。

两侧的视觉语气也不同：漫画侧是暖棕的书架（竖版书封、书名印在封面上），照片侧是暖白与曜石展陈墙。
换的是色相与材质，入口、进度、收藏与快捷键仍是同一套机制 —— 具体规格见[设计契约](./DESIGN.md)。

「未读」是待办队列而不是个人档案，它有独立页面 `/comic/unread`，由首页与侧栏进入，
不塞进「我的」。照片侧没有未读。

### 2.3 系统层

任务中心与设置通过水平页签打开各自的分区链接。运行区把任务状态、分析模块与本次运行摘要集中展示。清理、批量已读与备份恢复均先说明作用范围，再由用户确认。


任务中心（`/tasks`）与设置（`/settings`）属于系统层，**不与内容导航混排**：
侧栏里它们在独立的一组（本机），排在所有内容入口之后。先看内容，再管机器上的事。

两页各自用页内页签承载分区，页签 id 进 URL（`/tasks/run`、`/settings/interface`）：

- **任务中心**四段：运行（当前任务的进度与控制、等待队列）、每日计划（定时与模块选择）、
  任务记录（已完成 / 失败 / 取消，可筛选与清理）、本机存储（派生缓存占用与清理、
  各分析模块的权重与产物、路径）。
- **设置**四段：界面（外观与导航）、阅读（照片与漫画各自的密度、模式、适配与方向）、
  数据（媒体库索引、状态备份与恢复）、服务端（媒体根、缓存目录、访问控制等）。

磁盘占用属于任务，不属于设置——它是这次分析的后果。设置页管应用长什么样、怎么跑，
任务中心管跑得怎么样、占了多少。

分区链接位于标题下方。切换分区保留已访问表单的草稿。
界面分区的关于组展示版本与快捷键。清空索引和最近访问各自说明清理范围，经确认后执行。
任务状态连接中断时提供重连入口，缺少历史样本时保留实际张数并说明无法估算耗时。

任务中心在运行页的顶部给一条状态摘要：当前运行状态、队列里待处理的数量、以及当前可用的暂停、继续、取消或失败重试操作。失败摘要可直接打开对应记录。选模块、选增量还是全量、这次要处理多少张
与启动按钮一起排在状态之后；模块版本与运行环境属于高级信息，展开可见但不丢。

### 3.3 发现的维度

发现覆盖的是这几个**维度**：时间、人物、地点、主题、内容搜索。

维度集合是契约，**呈现方式不是**：这些维度可以同处一页（当前实现是顶部一个
发现入口加下方四段紧凑预览），也可以各自成页，或在入口处直接给出结果。
维度之间互不替代，也不该合并成一个「万能搜索」入口。已有路径（年份墙、人物、
足迹、主题墙、智能搜索）保持可用。

每个维度的入口都要能真正落到内容上：预览放真实内容（年份索引条、人物头像、
地点清单、主题条目、搜索框），分析结果缺失时写清为什么，不能摆一个点下去
空无一物的入口。

## 4. 核心页面职责

每个页面只回答一个问题。主操作与它服务的内容在同一屏可达；页面之间不重复同一份内容。

### 照片页 `/photo`

照片工作台的第一屏是**一条按时间下来的全库时间线**：全库照片按拍摄证据排成一条序列，
往下滚就是往回走时间。它回答的是「我想看看照片」，不回答「这个库由什么组成」。

时间线必须说清三件事：

- **这一段是什么时候**：精确到日和仅年月的证据按月分段；只有年份的证据单独按年分段，
  不补成一月或某一天。
- **这一段时间是怎么来的、精确到哪一级**：拍摄时间（EXIF）、文件名推断、目录推断、
  文件修改时间各是各的来源；界面还要区分精确到日、仅年月、仅年份与未知。单张照片
  优先用自己的 EXIF、文件名日期和有效目录日期，不能继承同相册其它照片推断出的代表日期。
  文件修改时间只说明文件最后改动的时间；只有它的媒体单独成段（「日期未知」），不混进任何一年。
- **怎么定位**：按年、按月、按照片 / 视频筛选，条件住在地址栏里（`/photo?year=2024`），
  刷新不丢、后退退得回、能分享。

**读不出来时说清是哪一类失败，并且给得出恢复的办法。** 首屏取不到时给出清楚的错误
信息与重试按钮，并区分断网、媒体库变化与服务端出错 —— 三者的下一步不一样，不能
一律写成「加载失败」。后续分页取不到时**已加载的照片仍然能翻**，失败的是没取到的那
一段，页面给一条可恢复的提示而不是把整页推倒。恢复之后从正确的游标继续往下走：
已加载的不重复也不丢。**失败状态下不自动续页** —— 自动续页会变成一条无限请求，
重试由用户发起。分页游标失效（媒体库变了）时说明要从头重取，而不是反复重试那一页。

年份索引中的 `unknown` 数量始终按全库当前媒体类型统计，不随所选年份或月份变化；
时间来源与日期精度统计则按当前筛选结果统计。这两组统计收在**可展开的说明**里：
数据解释能力必须保留（用户要判断哪些照片的时间可信），但它是解释而不是这一屏的
主内容，一直摊开会把注意力从照片上拽走。每一段标题上的「含推断时间」「仅精确到
年份」等标注常驻，不收进折叠区。

贴顶页头给出数量与年份区间，并提供媒体类型、筛选与密度。年份标尺支持快速定位，移动端在筛选浮层内选择年份和月份。相册入口位于全局侧栏。

「那年今日」默认展开为一行可横向浏览的照片；矮屏默认收起，标题可随时切换。优先取往年同月同日的照片，再按月日远近补足，最多 8 张。同一天的照片共用一个日期标签，往年同月同日只显示年份，邻近日期显示完整年月日。点照片可连续看大图，点大图标题回到原相册。
「接着看」位于照片带标题行，「随手看看」降为
次级功能（命令面板里的随机照片专页入口）。它们都不与时间线抢主视觉。「最近加入」搬去
相册页（照片侧那里按「按拍摄时间」排）。

**板块的取舍与顺序可以重做**：照片先于任务（任务型入口不压过内容型入口）、
空板块不占位（没有命中就不出现）是这两条不变的要求；除此之外，首页摆哪几块、
按什么顺序摆，都是当前实现，可以换。

照片页**不列全部相册**——那是相册页的事；**不列年份索引**——那是发现的事；
**不摆完整的主题墙**——那也是发现的事。这几块曾同时出现在首页与别处，造成同一内容
两处入口。照片页**必须**留着通往完整相册的明确入口：目录结构是「按文件夹找照片」的
主要路径，不能只靠用户自己发现。

### 相册页 `/photo/library`

结构页默认展示当前目录的通栏内容。目录树可按需打开，并在桌面保留展开偏好。

这一页以**真实目录**为主：屏幕上摆的是磁盘上真实存在的文件夹与相册，每一张卡都写清
它是什么、里面有多少张照片，以及点下去会发生什么。照片侧不出现「集合」这个词 ——
那是服务端的内部类型，用户看到的是「文件夹」。

目录树要能找回位置：

- **默认只展开当前位置相关的那条路**。媒体根那一行始终看得见（它就是库的第一层），
  但它的子项默认收着 —— 根下面常常挂着几十个年份文件夹，全部摊开就是一份巨大的
  导航列表，而内容区此刻正摆着同一批文件夹。站在哪一层，就只展开到那一层；其余收起。
- **可以收起**。每一层都能单独收起，树因此只显示需要的那几层。
- **可以搜**。目录可能很深，按名字定位到一处再跳过去，比一层层点省事得多。
- **面包屑可切换同级目录，也有返回父级**。走多深都要能一级一级退回来。

文件夹卡与相册卡**行为不同**：文件夹点开是下一层目录，相册点开是照片墙。两者
各自写清数量：文件夹写「N 个相册」，相册写「N 张」。文件夹卡的封面是目录里的真实
照片，可使用一至四张组成拼贴；「这是文件夹」由标题前的一枚小图标说清，
不再在封面上压一块常驻的黑标签（一屏几十个文件夹就是几十块黑条，把照片本身挤成背景）。

当前所在的目录、排序、筛选与视图都住在地址里：复制链接能落到同一个文件夹，刷新不丢，
前进后退能退回去。

**清单的分类方式与标题必须一致**：这一屏摆的是哪几类资源，标题与计数就说哪几类。
混合展示时不能把标题写成其中一种（「全部相册」摆在相册 + 文件夹 + 标签的清单上），
标题应跟着视图走。

相册页是唯一以"文件在哪儿"为答案的页面。

### 发现页 `/photo/explore`

找东西的页面。覆盖时间、人物、地点、主题、内容搜索这几个维度（见 §3.3）。

发现沿用全局搜索入口。点击侧栏搜索、窄屏搜索按钮或按快捷键打开命令面板，选择名称或画面与文字检索，提交后可在结果页继续编辑。下方依次是人物、地点、时间、主题，每段标题旁提供对应的完整入口。人物与地点的来源说明可点开阅读。各段独立加载，暂缺分析结果时显示原因及下一步。

各维度预览的形态：

- **时间**：一条横向的年份索引带，与 `/photo` 共用单张媒体时间证据和年份计数；
  点击进入 `/photo?year=YYYY`，照片范围与计数完全一致。只有年份精度的媒体计入该年，
  不补成某个月；只有文件修改时间的媒体留在「日期未知」。年份没有封面 —— 数字
  就是它的画面。
- **人物**：代表**脸本身**而不是整张照片；已命名与待确认分组
  分成两栏摆，候选分组不暗示已经确认身份（见 §5.7）。
- **地点**：去过的地方（城市粒度），卡片用真实的地理照片，带照片数并能点进地点详情；
  位置全部在本机解析，不请求在线地图。
- **主题**：只摆精选的少量几项，每张卡用实际成员的封面 —— 标题、照片张数、
  出自哪本相册写清楚；完整的主题清单在主题页。线索（时间 / 地点 / 人物 / 场景）
  收在悬停提示里，不逐张卡片挂一行灰字。

### 珍藏 `/photo/me`（漫画侧：`我的` `/comic/me`）

个人数据页。三个页签，页签 id 进 URL（`/photo/me/picks`），前进后退与深链可用，
切页签不丢状态（沿用设置页与任务中心的页签机制）。

- 照片侧：精选照片 / 收藏 / 最近浏览。
- 漫画侧：收藏 / 最近阅读 / 在读（读到一半的卷）；未读仍在待办队列。

三块数据的性质不同：精选是"这一张值得留着"，收藏是"这个资源值得留着"，
最近浏览是"我刚才在翻什么"。页面必须让这三者一眼可分，且不得只靠颜色相区分
（用形状、图标还是文案来分由设计决定，见 [DESIGN.md](./DESIGN.md)）；
收藏卡片需标明它是相册、文件夹、作品、卷或标签。

**三个页签用同一个容器**：标题、页签与照片展示区的左缘在同一条网格线上 ——
精选摆的是照片，收藏摆的是相册卡，最近浏览摆的是访问记录，形状不同，
起点必须相同。收藏摆的是相册与资源卡片（封面 + 名字），与精选的单张照片
一眼能分清；最近浏览只回答两件事 —— **翻的是什么、什么时候翻的**：
张数、视频数与目录类型是技术读数，那一页不摆。

**精选与收藏是两件事，名称、图标、提示与操作结果都不能混着说**：精选是照片级标记，
收藏是资源级标记（相册、文件夹、作品、卷、标签）。页签名、图标、空态与操作反馈
各自说各自的那一份；收藏的一侧不出现"收藏照片"这类说法。

**精选少到只有几张时换一种摆法**：照片墙是给"很多张"用的（密排、裁切、按固定行高铺满），
三五张用它排会缩在页面一角、竖幅还被裁掉半张。少量精选摆成陈列：每张一个框，
**完整地摆出来（不裁、不拉伸）**，框按照片自己的形状长，
框宽上限 520px，以原比例居中陈列。五张起改为自然比例的瀑布流。单张移出精选后可在提示中撤销。

**照片下面写来源与日期，不写文件名**：文件名（`IMG_20230824_224824.jpg`）是文件系统里的
编号，摆在照片下面读起来像一份技术清单；那里该写的是「哪本相册里的、什么时候拍的」。
日期按照片时间线同一套证据给（EXIF → 文件名 → 目录名），拿不出拍摄证据就不写 ——
文件修改时间不是拍摄时间。

### 相册照片墙 `/photo/albums/:id`

浏览页。页头压成一行：返回 · 面包屑 · 相册名 · 数量，右侧是密度、收藏与更多。

这一页要能让人**看见这本相册里的照片**，并按条件缩小范围。默认就是这本相册里的照片，
没有第二个入口把用户引到别处去。

**分组是同一批照片的一种看法，不是另一本相册。** 按时间、按人物、按地点、按场景
（或精选推荐）分组时，墙上仍然是这本相册里的照片，只是先看其中一组；面板里给出
「全部照片」那一条与「回到全部照片」的入口，数量要说清现在看的是哪一段。
原始照片集合**始终不变**：分组只是叠加在它之上的看法，切换分组不移动、不改名、
不删除任何文件。

原始照片墙的筛选（拍摄时间、已识别人物、地点、精选状态）**由服务端作用于整本相册**，
前端拿到的是筛好的结果与总数；条件可组合、逐条可去掉，没被算进来的照片要写清张数。
没有分析结果的那一段不摆入口，直接写清为什么不能用。

**筛选与分组不叠加，两者不许互相静默忽略。** 筛选条件属于原始照片墙；一个分组是
服务端算好的一段照片，它本身就是筛过的结果，再叠加条件只会让地址栏说着一套条件、
墙上摆着另一批照片。因此**进入某个具体分组时，与它冲突的筛选条件被明确结束**：
地址栏里一并去掉，界面上给出一次提示，并在这段分组视图里常驻一句话说明分组不再叠加
其它条件。**回到全部照片看到的是这本相册的全部照片**，不会意外恢复一条已经被结束的
筛选。多选的作用域是这本相册：换分组维度、进出分组都不清空用户已经勾上的照片。

**分组失效时由系统纠错，不打扰历史。** 分组被删除、被重建或 ID 失效之后，原先选中的
那一组已经不在了：页面自动退回全部照片。这是系统的纠错而不是用户的操作，因此**改写
当前那条地址，不往历史里追加失效的地址** —— 否则后退一次就多一条死链，来回打转停
不下来。用户主动选分组仍然进历史（后退键要能退回全部照片）；前进、后退、刷新与深链
都不形成循环。

分析覆盖率、重建分组与算法口径是**次级信息**：收在分组面板底部按需展开的「分析说明」
与分析 / 重建的更多菜单里。页面主视觉上是照片，不是分析进度。

**分组面板的空态分四种，每种给得出对得上的那一个操作**：还没分析（说清还差多少张没跑，
给补分析）、分析失败（失败的这些不参与分组，给重新分析）、分析跑完但没凑出分组
（给重建分组）、所需分析模块不可用（指向任务中心的模型状态）。人物分析没启用时指向
启用入口。空态说什么，底下就得给得出对得上的那一个动作。

### 中间目录页 `/photo/albums/:collectionId`（照片「文件夹」/ 漫画「作品」）

结构页：一个文件夹里的一堆相册。页头给出祖先面包屑（知道身在哪棵树上）与数量；
下面先给一条照片带（里面各相册的照片轮流取，每一本都露得出来，兼作快捷入口），
再给子项网格。中间目录是目录树的中间节点，它的计数是后代总数；照片侧的眉标与
计数单位说「文件夹」，漫画侧说「作品」。

相册页里的文件夹卡点开是**下一层目录**（留在相册页里），这一页是它的规范地址：
收藏、属性与复制链接都指向这里。

### 搜索结果 `/photo/search`

命令面板的全量提交进入搜索结果页。**检索对象分两档**：`scope=name` 查容器的名字
（相册、文件夹、标签），`scope=content` 查照片里的画面与图片文字。
两档用不同的后端接口，但结果页必须说清当前是哪一档 —— 作用域与关键词
都住在地址里（`?q=…&scope=…`），刷新、前进、后退都对。

结果要标明**对象类型、来源、数量与相关性**：名称结果按命中理由分组
（完全同名 / 开头相同 / 名字里含有 / 标签命中），理由当分组标题，不在每张卡上
重复同一句话；每张卡给出封面、名称、数量与来源。内容结果每张带命中方式
与相似度。

结果区是这一页的主角：索引覆盖率、模型是否就绪这类技术状态退到一行小字里，
不占主要空间。

页面给三件事：**返回**（应用内有历史就回退，深链打开时回发现页）、
**清除条件**（搜索框中的清除按钮同时重置关键词与作用域）、**重新搜索**（回车或点击输入框的提交按钮，再次执行当前条件）。已提交的词显示在顶栏输入框内，可直接改词。

三种「没搜到」必须分得开，**不得伪装成零结果**：

- **搜索失败**：请求本身没成功，给重试入口。
- **没索引 / 环境没准备好**：画面模型未就绪或还没建画面索引 —— 说清原因，
  给任务中心入口；用户要的是画面而系统只查了文字时，也要说清这一点。
- **真的没有**：都查过了，确实没有匹配。

### 内容搜索 `/photo/semantic`

找内容的地方，不找文件。一个主输入框，搜索方式用分段控件；同一个词同时检索画面语义与图片文字，
任一命中即显示，结果去重后统一排序与分页。以图搜图是独立入口，可附加图片文字筛选。
运行环境与已索引张数是卡片底部的一句备注，不与按钮并列。

### 主题墙 `/photo/smart-albums`

跨相册的智能分组汇成的一面墙。排的是**主题**，不是相册：默认按组内最新一张照片的拍摄时间倒序，
排序写进地址栏。推荐准入规则只在无结果时提示。往下滑自动接下一批。

### 发现与整理的性质差别

发现是只读的：它找到东西，不改东西。整理是写的：它改动分组状态与用户数据。
两者在导航上的次级程度不同，在视觉上也应当不同（整理区不该用主色强调）。

### 漫画首页 `/comic`

续读页。三个板块：继续阅读（在读的那一本 + 队列）、未读（还没翻开的）、
最近阅读（翻过的卷）。三者的分工：还在读的先接着读，没翻过的等一下，
翻过的是回访 —— 所以「继续阅读」永远排在最前，「最近阅读」排在最后。
没有续读内容时整块不出现——那里放着一枚点不动的按钮，读起来像坏了。
漫画库已有卷、但在读与未读都为空时，首页显示“还没有开始阅读”空态并提供书架入口，引导用户从已有内容开始。
作品与卷的清单在书架里，不在首页：漫画的组织方式是作品与卷，不是文件夹。

### 书架 `/comic/library`

结构页，与照片侧相册页同构：作品 / 系列 / 卷的一览与层级。作品是顶层集合，
系列是作品下的嵌套集合（目录层级里确实存在这一层时才出现），卷是叶级目录。
年份作为次级筛选保留，不取代作品与卷的主结构。

顶层按作品陈列，而不是把作品与卷摊平在一张网格里 —— 摊平了就是一排
混在一起的目录，谁也不知道谁是谁的一部分。顶层分两段：上面一段是作品，
下面一段是「未归入作品」的散卷（直接挂在根下、没有归入任何作品的卷）。
作品卡上写着这一部读到哪儿（`在读 · 第02话`），并给一个「继续读」的入口：
从书架一步进到读到一半的那一卷，不必先点进作品再找卷。
进到作品里面，列的是这一部的完整卷清单，跨卷导航（上一卷 / 下一卷、
读完自动切下一卷）以这份清单为来路。

### 相似照片与连拍 `/photo/similarity`

宽屏默认逐组审阅，左侧按类别、文件夹和状态列出分组，右侧并排比较成员。窄屏默认网格，点开一组进入全屏审阅。视图、筛选与当前组都可以通过链接重现。标记与忽略后衔接下一组，撤销按每组此前的状态恢复。人工决定仅修改本地整理记录。

**按处理状态组织，三档就是三档待办**：待处理 / 已处理 / 已忽略。
页面默认落在「待处理」——打开这一页就是为了看还有什么没处理；处理完的落到「已处理」，
不再看的落到「已忽略」。三档的组数在摘要里同时说清，筛选状态进 URL，深链能直接落到某一档。

三类结果按类别分开摆，各自带说明：完全重复按文件内容判定，近似重复按画面判定，
连拍只标出"同一个瞬间"，**不当成重复**。

**写操作的结果必须说清楚是哪一件事**：标记已处理、忽略、批量加入精选各有各的话，
不能笼统说成「已处理 N 组」——用户分不清自己刚才点的是哪一个。
标记与忽略会让这一组离开当前的待处理列表，因此这两种操作要留下**可撤销的入口**；
撤销按**每一组操作前的那一档**恢复：已忽略的组被标记为已处理之后，撤销要回到「已忽略」，
不是回到「待处理」；「全部」视图里跨状态批量操作时，每组各自回到自己原来的那一档。
用户在这之后又改过某一组时，那一组的撤销不生效，界面如实说「撤销不了」，不谎报恢复成功。

### 5.2 收藏与精选的区别

两份数据、两种语义，互不覆盖、互不清理：

- **收藏**是资源级：「这个资源值得留着」。可以收藏相册、集合、作品、卷、标签。
  **不存在照片级收藏**——想留一张照片，用精选。
- **精选**是照片级：「这一张值得留着」。只属于照片侧，存在照片级精选集合里。

界面上必须说得出差别：图形、配色与文案都分开（文案分开："收藏" / "精选照片"），
并且在「珍藏」里分属两个页签。具体用哪个形状、哪套颜色由设计决定（见
[DESIGN.md](./DESIGN.md)），但两者不得只靠颜色相区分。
清理失效收藏不会动精选，移出精选也不会动收藏。

### 5.3 浏览进度与阅读进度的区别

- 照片浏览**不留位置**。浏览历史记到**相册**上——用户翻的是照片，落点却是相册，
  因为照片没有"读到第几张"。因此照片侧只有"最近浏览"，没有进度条、没有"接着看第 N 张"。
- 漫画阅读**留位置**。进度精确到页，在读 / 已读 / 未读三态由服务端按真实活动派生。
  跨卷、续读、标记读完都建立在这个进度上。

同名的"接着看"在两侧含义不同：照片侧回到**那本相册**，漫画侧回到**那一页**。

### 5.4 原始文件夹与智能分组的关系

- **原始文件夹是事实**：磁盘上真实存在什么，相册页 / 书架如实呈现。它恒定不变。
  照片侧说「文件夹」，说的是磁盘上真实存在的目录；服务端内部把它叫「集合」，
  那个词不出现在界面上。
- **智能分组是结论**：主题、人物、足迹、年份墙都是叠加在原始之上的视图，由本机分析算出，
  随分析重建而变化。相册页里的分组面板也是这一类：它是这本相册里照片的一种看法，
  不是另一本相册。

智能分组**永不改写原始结构**：不移动、不改名、不删除、不覆盖任何文件。用户在人物页的改名 /
合并 / 隐藏、在智能分组里的改名 / 隐藏，都是**用户修正**，写进人工修正，重建索引后仍然生效，
不被下一轮分析覆盖。

两者可以交叉引用但不能互相替代：主题卡写着它出自哪本相册，人物详情写着它来自哪些照片，
点进去能回到原始结构里对应的那一本。

### 5.5 发现能力的边界

| 能力 | 回答的问题 | 不回答 | 归属 |
| --- | --- | --- | --- |
| 智能搜索（内容搜索） | 我拍过什么画面 / 哪些图里有这些字 | 我是谁、我在哪 | 照片 |
| 人物 | 谁出现在照片里（候选，需确认） | 真实姓名、身份 | 照片 |
| 足迹 | 我在哪、什么时候去的 | 精确到街道的位置 | 照片 |
| 智能相册（主题） | 这些照片凑在一起是什么 | 用户的分类 | 照片 |
| 原始文件夹（相册页） | 这些文件在哪儿 | 内容含义 | 两侧都有 |

内容搜索只查照片，不查漫画；人物、足迹、主题只属于照片侧；漫画侧只有作品、系列、卷与阅读状态。
四者互不替代，也不该合并成一个"万能搜索"入口。

### 5.6 日常浏览与高级整理

- **日常浏览**：打开、翻看、放大、筛选、搜索、跳转、继续读。它不写**整理类**用户数据
  （精选、收藏、分组修正、标记读完）。
  浏览历史与阅读进度是它的副产物：用户没点任何"保存"，但"我刚才在看哪本""这一卷读到
  第几页"必须自动记着，否则「最近浏览」「接着看」无从谈起。这类记录只描述"看过什么"，
  不改变任何内容，也不影响原始文件。
- **高级整理**：写入用户数据或改变分组状态——精选、收藏、相似组换代表 / 标记已处理 / 忽略、
  人物合并 / 改名 / 隐藏、批量加入精选、设置封面、标记读完 / 重置未读。

多选本身是浏览工具（勾选、对比），批量**写入**才是整理动作：勾选照片墙上的若干张是为了
挑选与比较，把它们批量加入精选是写操作，属于高级整理。

高级整理集中在「整理」与「珍藏」这类次级位置，不占一级导航，不挂在主操作按钮上，
并且每次都明确写出它改了什么（改了哪条数据、能撤销与否、会不会影响原始文件）。

### 5.7 分析派生数据的口径

后台分析算出来的东西有明确口径，界面按同一口径说话。

**人物分组是候选，不是身份。** 分三栏：

- **常见人物**：已由用户命名、分配或明确保留的组，以及出现张数达到门槛的组
  （门槛见 [架构文档](./ARCHITECTURE.md#媒体分析任务)）。
- **待确认匹配**：出现张数还没到门槛的未确认组。过去只收零星几张的小组，
  在列表里等于消失——这一档就是补这个缺口。每条匹配都要用户明确合并。
- **合照候选**：只在合照里出现的未确认组，按照片数、人脸数、脸部相对尺寸与检测分数排序。

候选相似度、差值与证据照片数是**复核线索，不是身份概率**。待确认匹配直接摆出提供互证的真实照片，
每条建议带风险分级（低 / 中 / 高）与中文风险原因（只有单张照片互证、两侧证据不足、与次优候选差距过小、
组内相似度分散、多数证据来自小脸、拍摄年份相隔过远）。分类不删除分析数据，搜索仍可查看全部组。

合照判定看脸数与脸部在画面里的相对尺寸，具体门槛同样见
[架构文档](./ARCHITECTURE.md#媒体分析任务)；分组还使用源图像素尺寸。确认组继续留在常见人物中。

**人物头像。** 发现、人物列表和人物详情共用方形头像。任务中心的「精选人物头像」逐张核对已分组的人脸，在同一人物的候选中优先选清晰正脸。详情可预览推荐头像、从该人物的其他照片选择或恢复自动精选。分组内没有可用人脸时展示占位图。

常见人物每批加载 50 组，列表按确认状态分区，只显示姓名和照片数。标注、分析设置、隐藏分组和清除数据收在「管理」中。

**未改名的人物分组按序数叫。** 候选组建立时只有哈希后缀，那串东西是给程序认的。改成按展示顺序编号
（「人物 1」「人物 2」，照片多的在前，同数按组内最小资源 ID）；序数会随分组集合变化重排，
用户一旦改名就固定下来（存在 `state/people-<model>.json`），改过名的分组不占号。

**智能主题的准入与证据。** 推荐同时依赖 EXIF 元数据、语义向量与人脸三个分析模块（人物线索需先在任务中心
启用人物分析）。推荐必须证据充分，卡片上写清由哪几类线索撑起来（时间 / 地点 / 人物 / 场景）；
质量分只参与后端排序，不上屏。详细分类覆盖时间、地点、人物与场景四类，只在来源相册内逐类检查。
证据不足的照片继续留在原始照片墙，不用"其它"分组强行归类。缺分析结果时写清原因，不摆空选项。

**相册的日期按三级取**：文件名 → 目录名 → 文件修改时间。相册的日期是它内部出现过的拍摄日期的**众数**
（按媒体数加权，并列取较早的）；集合的日期是后代相册日期的众数。按月日查询相册时，`matchedDate` 表示文件名命中的具体日期。
首页「那年今日」按单张媒体取日期，使用 EXIF 拍摄时间或文件名日期。漫画侧按加入时间浏览。
「没有时间」是一种缺失状态，不是公元 1 年。

**足迹的口径**：省、市、区县三级离线边界，不请求在线地图或地理编码；照片位置按网格聚合下发
（格边长随画布档位选择，见 [架构文档](./ARCHITECTURE.md#点位与网格)），不还原到单张照片的坐标。
行程与停留按相邻照片的日历日间隔区分——走过多个地方是「行程」，只在一个地方的是「停留」；
切分间隔由用户选（缺省 14 天），到访则按日历日间隔 ≤ 2 天算同一次，参数见
[API 文档](./API.md)。库里约四分之三的定位来自基站与网络，
不是 GPS 芯片，归属可能有百米量级偏差，页面要写明。

**相似照片分三类**：完全重复、近似重复、连拍同场景。折叠只是显示方式，不是筛选；
连拍组的画面本就不同，折叠它反而把不同的瞬间藏起来。

## 6. 关键用户路径

五条路径覆盖产品的五个动词。每条给出**从哪里进、经过什么、落在哪、留下什么痕迹**。

### 路径 1 · 随手看照片（观看）

打开应用 → 照片页第一屏是按时间下来的时间线 → 点开一张 → 大图预览左右翻 → `Esc` 退出 → 回到墙上原位。

- 落点：墙上的位置保持；浏览历史记到那张照片**出自的相册**。
- 痕迹：最近浏览新增一条（相册级）。
- 关键约束：退出预览后焦点回到打开它的那张照片；预览不留下进度，只有"我刚才在看哪本"。

### 路径 2 · 按时间找回一张照片（寻找）

照片页「那年今日」看到往年这一天拍过的那一张 → 点开 → 看这一张 → 从标题回到它所在的相册。
需要更宽的范围时：照片页的时间线按年 / 月定位 → 那一段的照片；或发现 → 时间 → 年份索引
→ `/photo?year=YYYY` → 同一套日期证据下的照片 → 照片。旧书签 `/photo/years/:year`
仍然打开按相册 / 目录年份取材的目录年份墙，页面名称与计数口径会明确区分。

- 落点：时间线对应年份中的大图预览；标题可点回来源相册。
- 痕迹：浏览历史记到来源相册；年份筛选不产生新的历史条目类型。
- 「那年今日」的每张照片都具有逐张的日期依据。往年同月同日排在最前，其他照片标明具体日期。没有符合条件的照片时，照片带不占位。

### 路径 3 · 读一本漫画并接着读（连续阅读）

切到漫画工作台 → 首页「继续阅读」显示上次那本与读到第几页 → 进入阅读器 → 翻页 / 切显示模式 →
读到末页给出收尾界面（有下一卷就接着读，没有就说清这是最后一卷）→ 退出。
明天打开：首页仍在「继续阅读」，位置接上。

- 落点：阅读器内的当前页；退出回到来源页（应用内有历史则后退，否则回那一侧的入口：漫画回书架，照片回相册页）。
- 痕迹：阅读进度按卷写入；读到最后标记已读。
- 关键约束：进度写的是**当前视图实际展示的最末页**（单页是当前页，双页是右侧页，连续是可见区末页）。
- 跨卷导航按**作品内的顺序**走，不绕圈：最后一卷没有下一卷，第一卷没有上一卷。
  收尾界面据此换一句话，也据此决定要不要留「下一卷」那个按钮 —— 没有下一卷时
  不留一个走不通的入口。

### 路径 4 · 找人与找地点（发现）

发现 → 人物：看常见人物缩略 → 进入某人 → 照片墙里框出这个人的脸 → 确认 / 合并 / 改名字。
发现 → 地点：看足迹的地图与行程 → 点行程卡上的地点链 → 地点详情 → 那几天的照片。

- 落点：人物详情 / 地点详情。
- 痕迹：人物页的合并与改名写进人工修正，重建后仍在；足迹页不写用户决定，它只是看
  （打开行程里的照片仍会记一条浏览历史）。
- 关键约束：人物是候选不是身份，界面不得暗示已识别；地点全部在本机解析，不请求在线地图。

### 路径 5 · 处理重复照片并把好的留下（整理）

整理 → 相似照片与连拍 → 逐组看：类别、张数、多余张数、三个质量数字 → 展开成员并排比较 →
点一张设为代表 → 标记已处理 → 批量把代表照片加入精选。

- 落点：仍在相似照片页，处理完一组下一组。
- 痕迹：换代表与处理状态写进人工修正（重建分组后仍生效）；加入精选写进照片级精选。
- 关键约束：不删除、不移动、不覆盖任何原始照片；连拍不算重复；折叠只影响显示。

| 照片级标记 | 精选照片 | 无 |
| 单张单位 | 张 | 页 |
| 历史 | 最近浏览 | 最近阅读 |
| 进度 | 无 | 在读 / 已读 / 未读 |

变更要点：**漫画侧不再把叶级目录叫「相册」**。同一个东西在一处叫相册、在另一处叫卷，
用户要记两套；漫画侧统一叫卷，与"第 1 卷""14 卷""还有 71 卷没读"一致。中间目录的词分侧：
照片侧说「文件夹」（磁盘上真实存在的目录），漫画侧说「作品」。

收藏统一称「收藏」而不称「收藏相册」或「收藏漫画」：它既保存叶级资源，也保存中间目录与标签。
这比初始方案中的「收藏相册」更准确，且不改变 `/favorites` 旧路径或资源级收藏语义；
「精选照片」仍专指照片级标记。

## 8. 外壳与导航规则

桌面侧栏顶部的工作台菜单在照片和漫画之间切换。切换记住偏好，并以一次普通导航进入目标工作台首页。侧栏搜索和快捷键打开同一个命令面板，发现页使用这个入口。搜索结果与内容搜索页在顶栏编辑当前查询。窄屏顶栏提供搜索按钮，更多抽屉内提供工作台分段切换器。

照片工作台的内容入口为照片、相册、发现、珍藏，整理组提供相似照片。漫画工作台提供首页、书架、我的、未读。首页固定，其他内容入口按导航偏好显示。相册与标签归属对应的结构入口，人物、足迹和智能相册归属发现。未读和待整理数量显示在所属入口；工作台切换后只使用对应库的数据。

任务中心和设置属于本机，两侧共用。当前任务可从侧栏状态摘要进入运行页。侧栏收起后保留图标、提示、完整的可访问名称和键盘导航。窄屏底部最多显示四个内容入口，其余进入更多抽屉。阅读器独占画布，大图打开时隐藏底栏。

- **名称结果**：输入后提供建议。方向键选中条目再按 Enter，或点击条目，打开对应资源。未选中时，Enter 打开首条完全同名的建议，其余查询进入名称结果页。Shift+Enter 或「查看全部结果」始终进入结果页。
- **画面与文字结果**：按 Enter 提交到 `/photo/search?q=…&scope=content`，结果页说明命中方式。
- **面包屑**：相册页与文件夹页给出祖先链（根 › 文件夹 › 子文件夹），祖先可点回；
  照片墙页头压成一行（返回 · 面包屑 · 标题 · 数量 · 动作）。
- **返回行为**：应用内有历史就后退；没有历史（直接打开的深链）则回**能确认的父级或来源**：
  1. **能确认上级就回上级** —— 相册回它所属的文件夹，文件夹回它的上级文件夹，
     卷回它所属的作品；
  2. **上级不明就回该侧的结构入口** —— 相册页 / 书架。那一页按目录把内容摊开，
     比回到工作台首页更接近「我刚才在翻什么」；
  3. 落点本身不能再指回自己：漫画卷的相册地址会重定向回阅读器，
     因此阅读器的回落是所属作品（或书架），绝不是这一卷的相册地址。

  照片侧的阅读器是另一回事：它放的就是这一本相册的内容，来路是那一面
  照片墙，因此回这一本自己的相册页，不跳过它回上级文件夹。

  兜底回落**替换**当前历史条目，不追加一条：深链打开时这一页就是历史里的第一条，
  再追加一条等于留了一枚死循环 —— 返回一次到上级，再返回一次又回到这一页。
  替换之后上级成为新的起点，继续按返回就一级一级往上走。
  地点详情有「返回足迹」，人物详情有「全部人物」。

## 9. 实施边界

本节说明这条线上的实施顺序与边界。各步按内容命名，不另起编号 —— 编号会与总体路线图的阶段混起来。

### 已落地 · 信息架构（不动视觉）

- 路由与页面骨架：`/photo/library`、`/photo/explore`、`/photo/me/:tab`、
  `/comic/library`、`/comic/me/:tab`。
- 旧路径重定向（见 §3.2），重定向是一次普通导航。
- 照片工作台的一级入口定名四个：**照片 · 相册 · 发现 · 珍藏**（§2.1）；
  漫画工作台独立，入口自成一套。
- 导航项清单（`utils/navEntries.ts`）与默认收起项已重建，服务端默认清单同步更新：
  默认收起项清空 —— 新导航每个入口都回答一个不同的问题，收起任何一个都会让那一类内容少一条路。
- 收藏页只显示当前工作台的收藏，不提示另一侧有多少项；全局收藏数据保留，清理操作只移除确认已不存在的资源。
- 侧栏分组、模式切换位置、面包屑按 §8 落地；返回行为按 §8 的三级规则落地：
  能确认上级回上级，上级不明回结构入口，兜底回落替换历史条目，不留回跳死循环。
- 照片侧移出年份索引与完整的主题墙（只留一屏主题预览）；漫画侧移出作品索引、
  年份索引与库内一览。
- 文案统一（§7.1），含漫画侧"相册 → 卷"。
- 快捷键目标随路由更新（`Ctrl+R` → 珍藏·最近浏览，`Ctrl+D` → 珍藏·收藏），
  `docs/SHORTCUTS.md` 同步。
- 测试：导航清单与路由重定向的 Vitest；旧路径可用性与新主链路的 E2E；受影响的布局断言同步更新。

**旧收起清单的迁移规则。** 服务端存的是**生效清单**（哪几个条目被收起了），不是差量。
旧版本留下的 key（`photo.favorites`、`photo.recents` 这类）在新的条目清单里不再匹配任何入口：
它们不隐藏任何东西，也不该被当成"用户收起了某个新入口"。
迁移**不重置用户偏好**——整份偏好（主题、侧栏折叠、上限等其它设置）与这份清单原样保留。
用户在设置·导航里改开关时是把整份清单写回（不是差量），这份里旧 key 仍在，
但它依旧匹配不到任何入口，所以侧栏的样子不变。
换句话说：旧 key 是惰性的，不是「未配置」，也不是「要清掉」——
唯一的例外是将来某条新条目恰好用了同一个 key，那时它会被读成"用户收起了这一项"。

### 已落地 · 视觉与交互

桌面侧栏可在展开和折叠之间切换，搜索入口在侧栏顶部。窄屏用顶栏打开搜索，由底栏和「更多」进入其余页面。照片时间线同行拼排稀疏月份，大图可从瓦片进入并返回。漫画书架使用 2∶3 封面，首页提供续读入口。设置与任务中心以水平页签切换分区，页签深链和草稿保留规则见第 8 节。设计尺度与验收方法见 [设计契约](./DESIGN.md)。

### 这条线上不做

- 不改 API 契约与数据模型：新页面用现有的 `/api/library/overview`、`/api/library/:id/children`、
  `/api/library/dashboard` 等接口即可支撑，不需要新接口。
- 不改路径安全、访问控制与媒体只读边界。
- 不引入新依赖。
- 不删功能、不做兼容层堆叠：废弃的入口与参数直接清掉，重定向是给书签的最后一次照顾。

## 10. 开放问题

- **手动标签与自建合集**：标签只能来自目录名里的方括号，且需 ≥2 本相册才形成智能集合；
  手动打标与用户自建合集需要新的写入面，与"应用对文件系统维持只读"这条边界相关，未定。
- **标签的入口位置**：标签页现在能从相册页的「标签」视图与命令面板的名称搜索进；要不要在目录树旁边
  给标签一个固定位置（而不是靠视图筛选找），待定。
- **自动发现文件变化的边界**：文件的新增、改写与删除已能自动发现并增量更新图库
  （见 [架构文档](./ARCHITECTURE.md#自动发现文件变化)）；仍待评估的是超大目录树下监听的句柄与
  事件开销、以及兜底校验扫描的频率取舍。
- **人物分组的准确率**：仓库没有可复现的人工标注集；历史本机小样本结果不足以定阈值，
  逆光、遮挡、跨年龄场景仍缺真实样本。评测限制与历史结果见 [架构文档](./ARCHITECTURE.md#人物评测)。
- **相似照片的误报率**：只有启发式阈值，没有标注集，误报与漏报未量化；现有人工抽查不代表系统评测，见
  [架构文档](./ARCHITECTURE.md#相似照片特征提取与分组对照)。
- **标签页的真实数据复核**：测试夹具覆盖特殊字符编码，但当前没有用户自己的标签库可供视觉复核；有真实标签数据时确认名称、来源与空态表达。
- **离线安装体验**：当前没有 PWA manifest 与 service worker；是否支持可安装和离线浏览需单独决定缓存及媒体失效语义。
- **发现的维度要不要继续拆**：地点（足迹）已经拆成独立路径，其余几块仍在一个页面里；
  若某个维度继续长大，再按同样方式拆出去，既有路径仍保留。
